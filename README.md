# stupidspeed

Measures the speed of programming languages in the simplest ways possible.

15 deliberately dumb micro-tasks × 61 toolchains × 35 languages = **915 cells**.
Every implementation is generated by an LLM from the exact spec below, so the matrix doubles as
an *AI code-generation benchmark*: does the model produce code that **compiles, is correct, and is fast**
in a language it rarely sees?

---

## Tasks

Each task prints a **single checksum line** to stdout and nothing else. The checksum is fixed and
verified — it exists purely to stop compilers from deleting the whole benchmark as dead code.

| # | Task | Spec | Expected stdout |
|---|------|------|-----------------|
| 01 | `counter` | increment an integer 1,000,000 times | `1000000` |
| 02 | `counter_concurrent` | 4 OS threads/tasks, each counting to 1,000,000, joined | `4000000` |
| 03 | `branches` | `i` in `[0,1e6)`: `if i%3==0` elif `%5` elif `%7` else; print 4 counts space-separated | `333334 133333 76190 457143` |
| 04 | `array_sum` | fill `int64[1_000_000]` with `a[i]=i`, sum it | `499999500000` |
| 05 | `func_call` | `acc = add(acc, i)` for `i` in `[0,1e6)`, `add` non-inlinable[^1] and in its own unit | `499999500000` |
| 06 | `char_count` | build `"abcdefghij"` ×100,000, count `'a'` | `100000` |
| 07 | `string_append` | append `'x'` to a string/buffer 1M times, print length | `1000000` |
| 08 | `fib_recursive` | naive `fib(40)`, no memoization | `102334155` |
| 09 | `fib_iterative` | loop `fib(40)` | `102334155` |
| 10 | `random` | LCG[^2] seeded 42, 1M draws, print `sum mod 2^32` | `4091189728` |
| 11 | `matrix_add` | 1000×1000, `A[i][j]=i+j`, `B[i][j]=i-j`, print `sum(C)` | `999000000` |
| 12 | `matrix_mul` | 500×500 naive triple loop, `A[i][j]=(i+j)%7`, `B[i][j]=(i*j)%5`, print `sum(C)` | `599995000` |
| 13 | `pi` | 10,000 digits of π (unbounded spigot), print digit sum | `44889` |
| 14 | `file_read` | read `data.bin` (100 MiB) and print `sum(bytes) mod 2^32` | see `reference/` |
| 15 | `file_write` | write 100 MiB of LCG[^2] bytes to `out.bin`, fsync, print bytes written | `104857600` |

[^1]: Defined in a separate compilation unit / marked `noinline` where the language allows it.
[^2]: `state = (1664525 * state + 1013904223) mod 2^32` — chosen because it stays exact in IEEE-754 doubles, so shells and `lua` produce identical output to `rust`.

### Rules

- No memoization, no closed forms, no SIMD intrinsics, no BLAS, no `numpy`. Idiomatic, straight-line code.
- Workload size is a compile-time constant; anti-DCE is the checksum, not artificial `volatile` noise.
- Stdlib only. Standard optimization flags only (`-O2`/`-O3`/`--release`), listed per toolchain in `toolchains.toml`.
- Task 14's input and task 15's output live in `tmpfs`/RAM disk when available; the flag is recorded in results.

## Methodology

- **Warmup 1, measured 5, report median** wall-clock; also record min, max, stddev.
- **Compile time and run time are separate columns.** JIT/VM startup counts as run time — it is real.
- Peak RSS recorded per run (`/usr/bin/time -v`, `Get-Process`, or `psutil` fallback).
- Hard timeout **300 s** per run; exceeded → `DNF`. Shells will DNF on tasks 11–13. That is the result.
- Checksum mismatch → `WRONG`, timing discarded.
- Each cell runs pinned to one core (`taskset`/affinity) except task 02, which gets 4.
- Scores are normalized to the `c/gcc` column (`1.00×`).

## AI scoring

Per model, across all 915 cells:

| Metric | Definition |
|---|---|
| **Build rate** | cells that compile/parse on the first attempt |
| **Correctness** | cells emitting the exact expected checksum |
| **Speed index** | geometric mean of `time / best_time_for_that_cell`, over correct cells only |
| **Idiom penalty** | manual review flag for cheating (hardcoded output, closed forms, memoization, BLAS) |

A model that writes correct Ada and correct Fortran is worth more here than one that writes fast Python.

## Layout

```
tasks/<task>/spec.md          canonical wording handed to the model
tasks/<task>/<lang>/<tc>/     generated sources + build recipe
reference/                    checksums and generated 100 MiB input
toolchains.toml               compilers, versions, flags, install hints
runner/                       harness: build, run, time, verify
results/<host>/<date>.json    raw samples
```

## Usage

```sh
runner/bench --task fib_recursive --lang rust        # one cell
runner/bench --lang c                                 # one column
runner/bench --all --jobs 1                           # full matrix (hours)
runner/report results/<host>/<date>.json --format md  # tables
```

Results are hardware-specific. Compare columns within one run; never across machines.
