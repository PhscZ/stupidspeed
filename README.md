# stupidspeed

Measures the speed of programming languages in the simplest ways possible.

15 tiny tasks, written in every language below, timed and compared.
The code is generated by an LLM from the specs in this file, so the results say two things:
how fast the language is, and how well the model writes languages it rarely sees.

## Rules

Every task prints one line and nothing else. The expected output is listed so you can check
the program actually ran instead of getting optimized away.

- No memoization, no math shortcuts, no SIMD, no BLAS, no numpy. Plain loops.
- Standard library only. Normal optimization flags (`-O2`, `--release`, etc.), listed in `toolchains.toml`.
- Same algorithm everywhere. Idiomatic syntax is fine, a different approach is not.

## Tasks

### 01 counter

```
count = 0
repeat 1000000 times:
    count = count + 1
print count
```

Output: `1000000`

### 02 counter_concurrent

Same loop, four times, on four threads at once.

```
function work():
    count = 0
    repeat 1000000 times:
        count = count + 1
    return count

start 4 threads running work()
wait for all of them
print sum of the 4 results
```

Output: `4000000`

### 03 branches

Four counters, one if/else chain, a million times.

```
a = 0; b = 0; c = 0; d = 0
for i from 0 to 999999:
    if i is divisible by 3:
        a = a + 1
    else if i is divisible by 5:
        b = b + 1
    else if i is divisible by 7:
        c = c + 1
    else:
        d = d + 1
print a, b, c, d
```

Output: `333334 133333 76190 457143`

### 04 array_sum

```
make array of 1000000 integers
for i from 0 to 999999:
    array[i] = i

total = 0
for i from 0 to 999999:
    total = total + array[i]
print total
```

Output: `499999500000`

### 05 func_sum

A function that adds 1, called 100000 times. Put it in its own file or mark it
no-inline if the language lets you, otherwise the compiler deletes the whole thing.

```
function add_one(n):
    return n + 1

value = 0
repeat 100000 times:
    value = add_one(value)
print value
```

Output: `100000`

### 06 char_count

Build a long string, then count the `h` characters with an if/else chain.

```
text = "abcdefghij" repeated 100000 times

count = 0
for each character ch in text:
    if ch == 'a': skip
    else if ch == 'e': skip
    else if ch == 'h': count = count + 1
    else: skip
print count
```

Output: `100000`

### 07 string_append

```
text = ""
repeat 1000000 times:
    text = text + "x"
print length of text
```

Output: `1000000`

### 08 fib_recursive

```
function fib(n):
    if n < 2: return n
    return fib(n - 1) + fib(n - 2)

print fib(40)
```

Output: `102334155`

### 09 fib_iterative

```
a = 0; b = 1
repeat 40 times:
    next = a + b
    a = b
    b = next
print a
```

Output: `102334155`

### 10 random

Same random number generator everywhere, written by hand. Not the built-in one,
those all differ. The numbers stay small enough that even languages without
64-bit integers get the same answer.

```
seed = 1
total = 0
repeat 1000000 times:
    seed = (1103515245 * seed + 12345) mod 2147483648
    total = total + (seed mod 100)
print total
```

Output: `49495104`

### 11 matrix_add

```
n = 1000
build A where A[i][j] = i + j
build B where B[i][j] = i - j
C[i][j] = A[i][j] + B[i][j]
print sum of all values in C
```

Output: `999000000`

### 12 matrix_mul

Plain triple loop, no tricks.

```
n = 500
build A where A[i][j] = (i + j) mod 7
build B where B[i][j] = (i * j) mod 5

for i, for j:
    sum = 0
    for k:
        sum = sum + A[i][k] * B[k][j]
    C[i][j] = sum

print sum of all values in C
```

Output: `599995000`

### 13 pi

10000 digits of pi with the unbounded spigot algorithm, big integers required.
Print the sum of the digits instead of the digits themselves, so the check is one number.

Output: `44889`

### 14 file_read

```
open data.bin (100 MiB, generated by reference/make_input)
total = 0
for each byte b in the file:
    total = total + b
print total mod 4294967296
```

Expected value is in `reference/checksums.txt`.

### 15 file_write

```
seed = 1
open out.bin for writing
repeat 104857600 times:
    seed = (1103515245 * seed + 12345) mod 2147483648
    write one byte: seed mod 256
flush and fsync
print number of bytes written
```

Output: `104857600`

## How it is measured

- One warmup run, then 5 timed runs, median reported. Min, max and stddev are saved too.
- Compile time and run time are separate columns. VM and JIT startup counts as run time.
- Peak memory recorded per run.
- 300 second timeout per run, then `DNF`. The shells will hit this on the matrix and pi tasks. That is a result, not a bug.
- Wrong output means `WRONG` and the timing is thrown away.
- Everything pinned to one core, except task 02 which gets four.
- Times are shown relative to `c/gcc`.

## Scoring the model

Across all cells, per model:

- **builds** - how many compiled or parsed on the first try
- **correct** - how many printed the expected line
- **speed** - geometric mean of `time / fastest time for that task`, correct cells only
- **cheating** - manual flag for hardcoded output, closed-form math, memoization, or calling a library that does the work

Getting Ada and Fortran right counts for more here than getting Python fast.

## Layout

```
tasks/<task>/spec.md         what the model is given
tasks/<task>/<lang>/<tc>/    generated code and build recipe
reference/                   checksums and the 100 MiB input generator
toolchains.toml              compilers, versions, flags
runner/                      build, run, time, verify
results/<host>/<date>.json   raw numbers
```

## Usage

```sh
runner/bench --task fib_recursive --lang rust        # one cell
runner/bench --lang c                                # one language
runner/bench --all                                   # everything, takes hours
runner/report results/<host>/<date>.json             # print tables
```

Numbers depend on the machine. Compare rows within one run, not across machines.
